## 1. 项目概述

### 1.1 背景与目标

用户正在学习日语 N5（JLPT 入门级），需要一个**纯前端、可部署到网络**的静态学习工具，覆盖「单词、语法、阅读」三大学习内容，并提供自测与进度记录，形成「学 → 测 → 复习」闭环。

MVP 目标：用最小工作量验证上述学习闭环的可用性与学习价值；内容**数据驱动**，后续扩充词库/语法/阅读量时无需改动代码结构。

### 1.2 用户画像

日语 N5 自学者；**主要使用 Windows PC（16:9 桌面比例）浏览器访问学习**，移动端（手机/平板）作为补充场景，仅需较好兼容。

### 1.3 MVP 范围（v1.0–v1.8，已交付）

**包含：**
1. 应用外壳：单词 / 语法 / 阅读 / 测验 四个学习模块 + 进度页（共 5 个导航项）的导航与切换，**以 Windows PC 16:9 桌面为主**的布局（移动端较好兼容）。
2. 单词模块：内置示例词库的列表浏览、搜索过滤、词卡详情（含例句）。
3. 语法模块：内置 N5 语法条目的列表与详情讲解。
4. 阅读模块：少量带假名注音、生词可查释义的短文。
5. 测验模块：**单词自测**（看释义选词 / 看词选释义）+ **语法自测**（v1.7 起以示例题库先行，见 §3.7），答题反馈、计分、错题回顾。
6. 进度记录：基于 localStorage 的本地进度（已学单词、测验记录、单词错词与语法错题清单）。

**不包含（非目标）：**
- 全量 N5 词库（约 800 词）与全量语法 —— 仅内置示例数据（见 §4.4），词库规模可后续扩充。
- 间隔重复（SRS）复习算法、每日提醒。
- 发音音频、假名书写练习。
- 账号系统、云同步、多设备进度。
- 后端服务与数据库（部署目标为静态托管）。
- PWA 离线能力、多语言界面。
- 语法题库规模：MVP 仅内置示例题（≥12 条，见 §4.4/§4.6）；**全量语法题库在正式版中填充**（见 §8）。

### 1.4 成功标准

- 在 Windows PC 浏览器（16:9 桌面，如 1920×1080、1366×768）中能顺畅完成「学 10 个单词 → 做一轮测验 → 查看错题」的完整流程；手机浏览器中同样可完成基本学习流程（较好兼容，不做深度优化）。
- 任意静态托管（GitHub Pages / Netlify 等）或本地双击 `index.html` 均可直接运行，无构建步骤、无外部 CDN 依赖。
- 词库数据文件可独立扩充，界面代码无需修改。

### 1.5 v2.0 正式版·阶段 A 范围（内容扩充）

MVP（v1.0–v1.8）已交付并部署上线（GitHub Pages）。v2.0 起进入**正式版内容扩充（阶段 A）**：**仅扩充数据文件，界面与引擎零改动**，按里程碑 M7–M11（§7）分批推进：

## 2. 技术形态与文件结构

### 2.1 总体约束

- 纯静态多文件站点：HTML + CSS + 原生 JavaScript（ES2017+），**不引入框架、不引入构建步骤、不依赖外部 CDN**。
- 数据文件以 `<script>` 方式加载（挂载到 `window.N5_DATA`），避免 `fetch` 在 `file://` 协议下的 CORS 问题，保证本地双击即可用。

### 2.2 文件结构（目标形态）

```
index.html              应用入口（单页，模块容器 + 底部/顶部导航）
css/style.css           全局样式（桌面优先、窄屏降级兼容）
js/app.js               启动与模块路由（显示/隐藏各模块视图）
js/words.js             单词模块逻辑
js/grammar.js           语法模块逻辑
js/reading.js           阅读模块逻辑
js/quiz.js              测验模块逻辑（出题、判分、错题）
js/progress.js          进度记录（localStorage 读写）
data/words.js           window.N5_DATA.words = [ ... ]   内置示例词库
data/grammar.js         window.N5_DATA.grammar = [ ... ] 内置语法条目
data/reading.js         window.N5_DATA.reading = [ ... ] 内置短文
data/quiz-grammar.js    window.N5_DATA.quizGrammar = [ ... ] 语法测验示例题库（v1.7）
scripts/validate-data.js Node 脚本：校验数据完整性（提交前验证用）
spec/mvp.md             本规格文档
```

> 说明：实现时若单文件过大可再拆分，但**必须保持“数据与逻辑分离、无构建、可直接静态部署”**三项原则。

## 3. 功能规格

### 3.1 应用外壳与导航

| 行为 | 说明 |
|---|---|
| 模块入口 | 顶部或底部固定导航：`单词 / 语法 / 阅读 / 测验`，点击切换视图，当前项高亮 |
| 默认视图 | 首次打开进入「单词」 |
| 布局 | **桌面优先**：面向 Windows PC 16:9（≥1280×720 等常见桌面分辨率）设计，内容区限宽居中、屏幕空间利用充分，页面在各桌面宽度下均完整美观；移动端较好兼容：窄屏（≥360px）自动堆叠为单列、无横向滚动、可读可用，但不承诺移动端专项优化 |
| 返回 | 详情类页面提供返回入口（返回按钮或导航重选） |

**验收：**
- A1 四个模块均可通过导航进入且内容正确渲染，无页面跳转（单页切换）。
- A2 桌面主场景：在 16:9 桌面视口（1280×720、1366×768、1920×1080）下浏览全部页面，内容限宽居中、排版完整美观、无横向滚动、无文字溢出；窄屏（≥360px）兼容浏览：无横向滚动、无文字溢出、可完成核心流程。

### 3.2 单词模块

**行为：**
- 列表视图：每行显示「汉字（若有）/假名/词性/中文释义」，点击进入词卡详情。
- 搜索框：按 汉字、假名（平假名/片假名）、中文释义 关键字即时过滤（忽略大小写）。
- 词卡详情：大字显示假名与汉字、词性徽标、中文释义、日文例句（带假名注音与中文翻译）；提供「标记为已学」按钮与「上一词/下一词」切换。
- 「已学」状态存储于进度（§3.6），详情页与列表中可显示标记。

**验收：**
- A3 内置词库全部词条可在列表中渲染，字段完整（见 §4.1）。
- A4 搜索：输入「わたし」「私」「我」均可命中对应词条；输入空串恢复全量列表。
- A5 点击任意词条进入详情，例句以「日文（带注音）+ 中文翻译」展示。
- A6 词卡可前后翻页；「标记为已学」后刷新页面状态仍保留（localStorage）。

### 3.3 语法模块

**行为：**
- 列表视图：分组展示语法条目（分组方式见 §4.2），每项显示「句型 + 简要含义」。
- 详情视图：展示 句型、含义、接续说明、例句（带注音与翻译）、注意事项。
- 条目较少时不要求搜索，但需支持分组快速定位（如按 助词/动词活用/句型 分组锚点或筛选）。

**验收：**
- A7 内置语法条目全部渲染，分组正确。
- A8 点击条目进入详情，五要素（句型/含义/接续/例句/注意）齐全且可读。

### 3.4 阅读模块

**行为：**
- 短文列表：标题（日文 + 中文副题）。
- 阅读视图：
  - 正文日文假名**注音完整**（汉字标注读音，使用 `<ruby>` 或等价方案）；
  - 生词（超出 N5 范围或属示例词库内关键词）**高亮可点击**，点击弹出释义浮层（假名、词性、中文释义）；
  - 提供「显示/隐藏中文翻译」开关。
- v2.0 内置 10 篇短文，篇幅 3~8 句，难度贴合 N5。
- **选材与语法多样性（v2.0.1 起，阅读重制导则）**：正文词汇取自 §4.1 词库（800 词，N5 范围），语法结构取自 §4.2 语法条目（74 条考点），篇内与篇间覆盖多样的 N5 文法结构——简体与敬体并用、〜ています／ていました、〜てから、〜たことがあります、〜つもりです、〜たい・〜がほしい、义务／许可／禁止（なければなりません・てもいいです・てはいけません・ないでください・なくてもいいです）、授受（てあげます／てもらいます／てくれます）、变化与选择（になります・くなります・にします）、〜とき・まえに・あとで、疑问词＋も／でも／か、形容词过去与否定、〜こと名词化、〜ごろ／〜ぐらい、〜と言います、句尾よ／ね 等；浮层生词（gloss）优先复用词库条目，避免句型和词汇同质化。

**验收：**
- A9 至少 3 篇短文可完整阅读，汉字均有注音（数据校验保证，见 §6）。
- A10 点击高亮生词出现释义浮层；浮层可关闭；关闭后页面无残留状态。
- A11 中文翻译开关即时生效且文案对应正确。

### 3.5 测验模块（单词自测）

**行为：**
- 出题模式：两方向混合 —— ① 显示中文释义，从 4 个日语词中选择正确项；② 显示日语词（假名/汉字），从 4 个中文释义中选择正确项。
- 题量与范围：每轮 10 题；题目默认从**全部词库**随机抽取，选项干扰项从词库中选取（优先同词性/同首字，不足则随机），保证选项不重复。
- 答题流程：选择答案后**立即反馈**（对/错 + 正确答案），点击「下一题」继续；答错题目自动记入错题清单（§3.6）。
- 结算页：显示本轮得分（对 X/10）、按对错分列回顾题目；提供「再测一轮」与「只测错题」入口（错题不足 5 题时提示并允许全库重测）。
- 连续性：中途刷新页面不要求恢复进行中的一轮（MVP 不承诺），但**已结束轮次的记录**必须持久化。

**验收：**
- A12 一轮固定 10 题、每题 4 选项且选项不重复；正确项唯一。
- A13 选对/选错均有即时视觉反馈与正确答案提示。
- A14 结算页得分正确（与答题结果一致），错题清单与作答一致。
- A15 「只测错题」仅从错题清单出题；答对可正常计分且答题后不再计入该轮新错（错题清单在答对后移除，规则见 §3.6）。
- A16 词库少于 4 词等边界情形（数据校验已保证 ≥20 词，见 §4.4）不会产生死循环或崩溃；任何情况下页面不白屏。

### 3.7 语法自测（v1.7 引入，MVP 示例题库）

**行为：**
- 测验模块提供开局选择：**单词测验 / 语法测验**；语法测验每轮从语法题库（`quizGrammar`，见 §4.6）随机抽取 10 题，每题 4 个不重复选项（以填空 `＿` 形式给出含句型/助词的日文题干 + 中文提示）。
- 作答后即时反馈并展示**解析（explain）**；答错题目 id 加入 `n5app.wrongGrammar` 清单（答对即移除），与单词错题分开管理。
- 结算页得分与错题回顾同 §3.5；「只测错题」对语法题同样生效（语法错题为空时提示并转全题库重测）。

**验收：**
- A21 语法测验每轮 10 题、每题 4 个不重复选项、正确项唯一，题干含填空位与中文提示。
- A22 语法题作答有即时对错反馈与解析展示；答错进入 `n5app.wrongGrammar`、答对移除，刷新后保持。
- A23 语法题与单词题在同一结算/进度体系内互不串扰（得分按轮记录，含题型标注）。

### 3.6 进度记录（localStorage）

**数据模型**（存储键统一前缀 `n5app.`，详见 §4.5）：

- 已学单词集合：`learnedWords`（词条 id 数组）。
- 测验历史：`quizHistory` —— 每次结算追加一条 `{ date, total, correct, wrongIds[] }`，保留最近 20 条。
- 错题清单：`wrongWords` —— 测验答错的词条 id；同一词条在**后续测验中答对**时移除，答错时保留。
- 进度页/入口：展示 已学词数、累计测验次数、最近一次得分、当前错题数，并可查看错题列表（点击跳转词卡详情）、重置进度（二次确认）。

**验收：**
- A17 测验答错词进入错题清单；后续答对该词后清单移除该词，持久化正确。
- A18 已学标记、测验历史在刷新/重开页面后仍保留。
- A19 重置进度二次确认后，全部 `n5app.*` 键清除，应用回到初始状态且不报错。
- A20 localStorage 不可用（如隐私模式被禁）时，应用仍可正常浏览与测验（仅不持久化），不抛异常。

## 4. 数据规格

### 4.1 单词（word）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| id | string | ✔ | 唯一，格式 `w0001` 起递增 |
| kana | string | ✔ | 读音，全假名（平/片假名均可） |
| kanji | string | - | 汉字写法；纯假名词省略 |
| pos | string | ✔ | 词性（名词/动词/形容词/代词/副词/助词…） |
| meaning | string | ✔ | 中文释义（分号分隔多义） |
| example | object | ✔ | 例句：`{ jp, cn }`；`jp` 为日文例句（**v1.5 起汉字须带注音标记**，语法同 §4.3：汉字串后紧跟 `{よみ}`），`cn` 为中文翻译 |
| reading | string | - | 可选：例句注音辅助标记（预留字段） |

示例：
```js
{ id: "w0001", kana: "わたし", kanji: "私", pos: "代词",
  meaning: "我", example: { jp: "私{わたし}は学生{がくせい}です。", cn: "我是学生。" } }
```

> v1.5 说明：例句 `jp` 中的汉字注音标记用于词卡例句的注音朗读展示（验收 A5）；数据规模与词库结构不变，仅 `example.jp` 内部文本升级为带注音写法，由 `scripts/validate-data.js` 校验全覆盖。

### 4.2 语法（grammar）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| id | string | ✔ | 唯一，`g0001` 起 |
| pattern | string | ✔ | 句型，如 `～は～です` |
| group | string | ✔ | 分组：`助词 / 动词活用 / 句型`（MVP 三组） |
| meaning | string | ✔ | 含义简述 |
| connect | string | ✔ | 接续说明 |
| examples | array | ✔ | ≥1 条 `{ jp, cn }`；`jp` 为日文例句（**v1.6 起汉字须带注音标记**，语法同 §4.3），`cn` 为中文翻译 |
| note | string | - | 注意事项/易错点 |

示例：
```js
{ id: "g0001", pattern: "～は～です", group: "句型",
  meaning: "…是…（判断句）", connect: "名词 + は + 名词 + です",
  examples: [ { jp: "わたしは田中です。", cn: "我是田中。" } ],
  note: "口语中「です」可弱读为「っす」。" }
```

### 4.3 阅读短文（passage）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| id | string | ✔ | 唯一，`r0001` 起 |
| title | string | ✔ | 日文标题 |
| titleCn | string | ✔ | 中文标题 |
| body | string | ✔ | 正文段落（按行/段分隔），**包含注音标记**，见下 |
| gloss | array | ✔ | 生词表：`[{ word, kana, pos, meaning }]` |
| cn | string | ✔ | 全文中文翻译 |

正文注音与生词标记采用内联轻量标记，渲染时转换（避免 `<ruby>` 手写冗长）：
- 注音（v1.4 起）：汉字后紧跟假名注音组 `漢字{よみ}` → `<ruby>漢字<rt>よみ</rt></ruby>`。多汉字词整体注音：`日本語{にほんご}`；带送假名的词只注汉字部分：`行{い}きます`。
- 生词（可点击查义）：`*語{よみ}*` —— 词内含汉字时同样汉字后置注音（如 `*毎日{まいにち}*`）；纯假名生词可写作 `*ことば*`。渲染为高亮 `<span class="gloss" data-i="n">`，n 为该生词标记在正文中的**出现顺序**（0 起），对应 `gloss` 数组下标。
- **覆盖规则（校验要求）**：正文中每个汉字字符组（连续汉字串）必须紧跟一个假名注音组 `{…}`（含生词标记内的汉字），保证全文可注音朗读。

示例片段：
```
私{わたし}は*毎日{まいにち}*学校{がっこう}へ行{い}きます。
```

### 4.6 语法测验题（quizGrammar，v1.7 起）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| id | string | ✔ | 唯一，`gq0001` 起 |
| question | string | ✔ | 日文题干（含且仅含一个填空位 `＿`） |
| hint | string | ✔ | 中文提示（句意或考点引导） |
| options | array | ✔ | 4 个不重复选项（字符串） |
| answer | number | ✔ | 正确选项下标（0–3），对应 `options` |
| explain | string | ✔ | 解析说明（正确选项选对/错后均展示） |

示例：
```js
{ id: "gq0001", question: "まいにち7じに＿。", hint: "每天七点起床（现在习惯）",
  options: ["おきます", "おきました", "おきません", "おきたいです"], answer: 0,
  explain: "毎日表习惯 → 用「ます形」（现在/将来）。" }
```
